# Atlas Scholarship Intelligence — EDXSO AI Engineer Intern Assignment 2

A trust-first scholarship intelligence crawler for Indian students.

## What is built
**Discover → Crawl → Extract → Verify → Score → Store → Update**

The prototype starts from a small set of authoritative seed sources, discovers scholarship cards/programmes, normalizes them into a common schema, retains official source URLs and evidence, computes an evidence-driven confidence score, stores records in SQLite, and preserves field-level changes across repeated runs.

## Assignment output
- 20 real scholarship records in the packaged primary-source verification cache.
- 18 records at **VERIFIED / ≥95%** confidence.
- 3 source types: Government, University, Corporate.
- 2 documented deadline changes with old value, new value, date, source and evidence.
- 2 expired/stale examples.
- Searchable Streamlit dashboard and inspectable SQLite database.
- No fabricated values: unavailable fields are `Not specified`.

## Stack
Python, Requests, BeautifulSoup, SQLite, Streamlit, pytest. All are free/open-source or free runtime components. No paid APIs or paid scraping services.

## Architecture
```text
Authoritative seed pages
        ↓
Discovery / source classification
        ↓
Requests + BeautifulSoup
        ↓
Structured extraction
        ↓
Primary-source verification + evidence ledger
        ↓
Deterministic confidence engine
        ↓
SQLite repository
        ↓
Change detection + stale status
        ↓
Streamlit dashboard / CSV
```

## Confidence methodology
The confidence number is **not generated by an LLM**. The deterministic score uses:
- 25 — official primary domain
- 15 — application route retained
- 10 — identity/provider extracted
- 15 — field-level evidence retained
- 10 — verification timestamp
- 10 — deadline directly supported
- 5 — status classified
- 5 — source type classified

`VERIFIED` is assigned only at **95 or above**.

## Anti-hallucination
If an official page does not expose a field, the system writes `Not specified` or points to the official specification/FAQ. It never fills an unsupported amount, income threshold, deadline, age rule or document list from model knowledge.

## Change detection
The repository does not simply overwrite previous values. It writes field-level changes to `change_history`.

The packaged evidence ledger demonstrates two documented 2026 changes:
1. **NMMSS:** 30-Sep-2026 → 31-Oct-2026 (official PIB extension).
2. **Beedi/Cine/IOMC/LSDM Pre-Matric:** 31-Aug-2026 → 30-Sep-2026 (official PIB extension).

The old value, new value, detected date, official source and evidence are retained.

## Source policy
Aggregators may be used for discovery research, but the repository's authoritative source must be a government, official university, or official provider page. The packaged records were reviewed against official pages/notifications during development.

## Limitations
Some official portals expose full eligibility through linked PDFs, FAQs, login pages or application flows. The system intentionally records missing details as `Not specified` rather than guessing. Captcha/login/private endpoints are not bypassed.
